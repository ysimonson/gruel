# tree-sitter-gruel

[Tree-sitter](https://tree-sitter.github.io/tree-sitter/) grammar for the
[Gruel programming language](https://github.com/gruel-lang/gruel),
purpose-built for editor / IDE integrations.

The canonical Gruel parser ships with the compiler in
[`crates/gruel-parser`](../crates/gruel-parser/). This tree-sitter grammar
exists alongside it, not in place of it — it provides incremental,
error-tolerant parsing for highlighters, structural-edit tools, and (in
the future) the language server. Acceptance parity between the two
parsers is enforced by the `parser_differential` fuzz target
(`fuzz/fuzz_targets/parser_differential.rs`) and a spec-corpus
differential test (see [ADR-0090](../docs/designs/0090-tree-sitter-and-parser-differential.md)).

## Layout

```
tree-sitter-gruel/
├── grammar.js           # Grammar source — edit this
├── package.json
├── src/                 # Generated by `tree-sitter generate` — committed
├── bindings/rust/       # Rust crate wrapping parser.c (Phase 4)
├── queries/             # Editor queries (Phase 7)
└── test/corpus/         # Tree-sitter's native corpus tests
```

The generated `src/` directory is committed so that contributors who only
need to build the parser (or run the differential fuzzer) don't need
`node` or `tree-sitter-cli` on their machine.

## Regenerating after editing `grammar.js`

You need a one-time install of the local tree-sitter CLI:

```bash
cd tree-sitter-gruel
HOME=$(pwd) npm install --cache ./.npm-cache    # respects sandbox cache permissions
```

Then, from the repo root:

```bash
make tree-sitter-generate    # regenerate parser.c
make tree-sitter-test        # run corpus tests
```

Both targets cd into `tree-sitter-gruel/` and run the local
`node_modules/.bin/tree-sitter`, so you do not need a globally installed
CLI.

## Editor integration

### Neovim (`nvim-treesitter`)

Until the grammar is published to crates.io / npm and registered with
`nvim-treesitter`, point at this directory directly:

```lua
local parser_config = require('nvim-treesitter.parsers').get_parser_configs()
parser_config.gruel = {
  install_info = {
    url = '/path/to/gruel/tree-sitter-gruel',
    files = { 'src/parser.c' },
    branch = 'main',
  },
  filetype = 'gruel',
}
```

Place the contents of `queries/` under
`~/.local/share/nvim/site/queries/gruel/`.

### Helix

Add to `~/.config/helix/languages.toml`:

```toml
[[language]]
name = "gruel"
scope = "source.gruel"
file-types = ["gruel"]
roots = []
comment-token = "//"
indent = { tab-width = 4, unit = "    " }

[[grammar]]
name = "gruel"
source = { git = "...", subpath = "tree-sitter-gruel" }
```

Run `hx --grammar build` after editing the config.

### Zed

Zed reads tree-sitter grammars from a Zed extension. Once we publish a
Zed extension for Gruel it will simply point at this directory. For now,
clone the repo and follow the local-extension guide at
<https://zed.dev/docs/extensions/languages>.

## Status

This grammar covers all syntax that `gruel-parser` accepts, structurally.
Tree shape is optimised for tooling queries and does not match the
compiler AST exactly — they are different parsers serving different
audiences. Parity is *acceptance only*: both must agree on whether a
given input is syntactically valid.

The grammar is iterated alongside the rest of the language; new Gruel
syntax should land in the same PR that updates `grammar.js`. See
[ADR-0090](../docs/designs/0090-tree-sitter-and-parser-differential.md)
and the "Modifying the Language" section of the repo's `CLAUDE.md`.
